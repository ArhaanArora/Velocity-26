## Required behavior

### Normal operation

Under normal traffic, the fictional server should:

- Serve most legitimate requests.
- Have low resource utilization.
- Maintain a small or empty queue.
- Report high legitimate-user availability.

### Traffic overload

When the simulated excess request rate increases:

- Incoming traffic increases.
- Resource utilization increases.
- The queue may grow.
- Requests may be dropped when capacity is exceeded.
- Legitimate-user availability can decrease.
- Approximate latency can rise.

### Resource model

Track four abstract server resources:

- CPU utilization.
- Bandwidth utilization.
- Connection utilization.
- Request queue utilization.

These are educational approximations, not measurements of real network equipment.

Each resource should have a clear, documented relationship to the model's current state.

### Consistency

- No negative metrics.
- Percentages always between 0 and 100.
- Queue never exceeds its configured capacity.
- No requests counted twice.
- Preserve consistent accounting between simulation ticks.
- No random numbers.
- Same input state and configuration must produce the same output.
- Do not mutate the previous state.
- Limit history to 60 snapshots.
- Initial state should be valid and usable immediately.
